## 1. Семантика меток организатора (read-only, значения gold не использовались)

Источники: «Легенда к матрице.docx», «ПОДРОБНЫЙ ПЕРЕЧЕНЬ …docx» (4 страницы-картинки: Приложение 19 к Регламенту Комитета государственного строительного надзора г. Москвы, «Примерный перечень исполнительной документации»), листы «Правила разметки» и «Нормативные 5» закрытой книги (только текст правил), ТЗ 9.2, Приложение 2.

| Метка | Когда ставит организатор | Основание |
|---|---|---|
| `VIOLATION_PRESENT` | значения сопоставлены, **триггер параметра выполнен**, есть точные доказательства (file + page) — либо отдельный контур FREE_SEARCH | «Правила разметки», п. 2 |
| `NO_VIOLATION` | **только после явного сопоставления**; `UNREVIEWED` и `MISSING` отрицательными не являются | п. 3 |
| `MISSING_DOCUMENT` (+ `PD_/RD_/ID_MISSING`) | отсутствует документ (стадия/раздел), из-за которого параметр **не проверен**; хранится отдельно и **не подменяет инженерное нарушение**; в Приложении 2 раздел 3 — параметр + имя недостающего файла | п. 4; ТЗ 9.2 («отсутствующий документ маркируется как MISSING»); Прил. 2, р. 3 |
| `COMPARISON_IMPOSSIBLE` | документы есть, но сравнение невозможно (доступен один тип/ни одного; нет сопоставимых источников); для скрытого теста — категория «конфликт редакций» | ТЗ 9.2 («один тип или ни одного → COMPARISON_IMPOSSIBLE»); ТЗ 14.2 |
| отсутствие ИД | нельзя объявлять нарушением без стадии строительства и применимости; перечень ИД — ориентир, акты п. 10.4–16 проверяются «по окончании строительства» | п. 6; Приложение 19 |
| ИД не обязателен для попарной проверки | у публичных положительных строк `document_status = PD_RD_AVAILABLE_ID_NOT_REQUIRED_FOR_PAIRWISE_CHECK` — отсутствие ИД не делает ПД↔РД-сравнение невозможным | публичный `public_train_checks.jsonl` |

**Принятое отображение** (это наше прочтение: в материалах организатора точная граница между `MISSING_DOCUMENT` и `COMPARISON_IMPOSSIBLE` не задана — см. вопросы в разделе 7):

1. Требуемая стадия (или требуемый раздел на стадии) **отсутствует и это доказуемо** → `MISSING_DOCUMENT` со статусом самой тяжёлой отсутствующей стадии (ПД > РД > ИД, как в таблице статусов ТЗ 9.2).
2. Документы есть, но сравнение невозможно (нет извлекаемого значения, конфликт редакций, несопоставимые величины/единицы, самосравнение, параметр «на каждый элемент», триггер не проверяем по значениям) → `COMPARISON_IMPOSSIBLE` **с машинной причиной** в `delta.reason`.
3. Значения сопоставлены, триггер не выполнен → `NO_VIOLATION` (`delta.reason = change_not_triggering`, если значения различались).
4. Триггер выполнен → `VIOLATION_PRESENT` (`CANDIDATE` до решения инспектора).
5. Нет ИД, но ПД↔РД сравнимы → сравнение остаётся (как и раньше), статус комплектности `PARTIALLY_LOADED`.

## 2. Гейт

Порядок по ТЗ 9.2 п. 3. Каждая причина детерминирована и записывается в `delta.reason` / `delta.gate`; метка экспорта — `MISSING_DOCUMENT` (только причины отсутствия) либо `COMPARISON_IMPOSSIBLE`. Гейт **никогда** не превращает воздержание в вердикт.

| # | Причина | Что проверяется | Метка |
|---|---|---|---|
| 1 | `trigger_not_evaluable` | тип триггера `NOT_EVALUABLE` (пространственные/реестровые) | COMPARISON_IMPOSSIBLE |
| 2 | `multi_instance_parameter` | параметр «на каждый элемент» (двери, коридоры, стояки, кабели…; 24 кода, каждый с обоснованием из формулировки каталога), а механизм читает одно число на стадию | COMPARISON_IMPOSSIBLE |
| 3 | `missing_discipline_document` | на стадии есть файлы, но нет ни одного раздела, названного в каталоге (`source_pd/rd`); «нераспознанный» файл никогда не доказывает отсутствие | MISSING_DOCUMENT |
| 4 | `revision_conflict` | процитированный файл — один из нескольких **неупорядочиваемых** изданий раздела (Корр.1 / МГЭ / v5; серия ЖС-РД-270121 против 2025-04; «ПД 2022» против «ПД 2025») | COMPARISON_IMPOSSIBLE |
| 5 | `self_comparison` | ПД- и РД-доказательство — один и тот же файл или байт-в-байт одинаковые файлы | COMPARISON_IMPOSSIBLE |
| 6 | `evidence_discipline_mismatch` | страница взята из раздела, не названного в каталоге для этой стадии: числовой/составной/счётный механизмы — ПД и РД; enum — **только РД** (класс легитимно повторяется в томах ПД ПЗ/ПБ/ОДИ/АР, но в РД авторитетен лист, названный каталогом, — «АР/КР: Общие данные», а не общие указания листа молниезащиты) | COMPARISON_IMPOSSIBLE |
| 7 | `unit_mismatch` / `unit_evidence_absent` | рядом с числом иная физическая единица (высота вместо объёма) либо единицы параметра нет ни рядом, ни в строке, ни в заголовке столбца над числом (номер пункта, маркер списка, дата) | COMPARISON_IMPOSSIBLE |
| 8 | `magnitude_mismatch` | ПД/РД отличаются в ≥20 раз — разные величины/единицы | COMPARISON_IMPOSSIBLE |

Документные факты (`document_facts.py`) считаются только по манифесту и имени файла (страницы не открываются, результат воспроизводим побайтно):

* **упорядочиваемые** редакции (`кор2 < кор3`, `Изм.1 < Изм.3`) → побеждает новейшая, остальные — `superseded` и **не попадают в generic-кандидаты** (у Речникова почти каждый раздел ПД — оригинал + кор2 + кор3: это норма, не конфликт);
* **неупорядочиваемые** (разные виды маркеров, две «кор3», разные серии шифров, разные папки-поколения) → конфликт;
* корпуса `К1/К2`, листы `…_6`, архивы `.zip/.7z/.dwg` рядом с PDF — не редакции;
* шифр `01_07.22` не читается как дата, `ЖС-РЛ-0624-2024` — как год (маркеры берутся только из хвоста имени после раздела).

## 3. Политика триггеров

`reports/trigger_policy_132.md` — полная ревьюируемая таблица (код, тип, `needs_review`, комментарий, **дословный текст каталога**); `.json` — машинная версия. Сверка «текст в таблице = текст каталога» — тест `test_embedded_text_has_not_drifted_from_the_catalog`.

| Тип | Кодов | Семантика при различающихся значениях |
|---|---|---|
| DECREASE | 37 | нарушение только при уменьшении (опц. порог %) |
| INCREASE | 12 | только при увеличении (опц. порог %) |
| ANY_CHANGE_PCT | 27 | любое изменение / изменение > x % (`ANY_CHANGE` = `pct 0`; консервативный тип для неоднозначных) |
| ABS_THRESHOLD | 15 | значение РД/ИД против порога (`<`, `>`; `SPZU-034` — порог на смещение); чужая единица/порядок → `UNDETERMINED` (кандидат сохраняется) |
| ENUM_DOWNGRADE | 12 | ухудшение класса по порядку (I…V, C0…C3, КМ0…КМ5, A++…E) или по числу (B35→B30, С345→С245, А500С→А400) |
| PRESENCE | 12 | элемент был в ПД и исчез в РД |
| COUNT_CHANGE | 4 | любое изменение числа |
| NOT_EVALUABLE | 13 | воздержание (`trigger_not_evaluable`) |

Консервативность: неоднозначный триггер → `ANY_CHANGE` либо более широкая граница диапазона («менее 1.5–1.8 м» → `< 1.8`); значение, для которого триггер решить нельзя (`UNDETERMINED`), остаётся `CANDIDATE`. Таблица может только **убрать** кандидата, чья динамика заведомо не удовлетворяет триггеру; равные значения по-прежнему `NEGATIVE_VERIFIED`, новых кандидатов она не создаёт. Rule-pack тир (`PZ-009, KR-055, KR-058, IOS4-078, IOS4-079`) не менялся.

## 7. Ограничения и открытые вопросы

1. **Главная цена — правило конфликта редакций.** По спецификации промпта (2б) несколько поколений проекта в одной стадии/разделе → `COMPARISON_IMPOSSIBLE`. На трёх объектах с двумя поколениями ПД (DOO25 «ПД 2022/2025», POL17 «Корр.1 / МГЭ / v5», ALT79B три серии шифров) это снимает и верные пары: 10 из 15 потерь recall на посевах стенда A. Стенд A для этих объектов вручную определил, какому поколению следует РД; система этого по метаданным сделать не может. Если организатор трактует конфликт иначе — это одна точка (`comparison_gate.GateContext.evaluate`, шаг 3).
2. **Гейт раздела для enum на RD-стороне** (класс, переписанный в общие данные листа МЗ/НК, не считается значением АР/КР) снял ложный CANDIDATE LOS3A PZ-022, но и 2 посева LOS3A PZ-023 (значение с листа НК2). Обоснование — источник, названный каталогом; альтернатива — снять правило (строка `_EVIDENCE_DISCIPLINE_STAGES["enum"]`).
3. **Единственное истинное нарушение SILVER (LOS3A SPZU-024) не найдено ни до, ни после по существу:** до — `CANDIDATE` на значениях «2.10» (номер пункта) и «88,00» (другая строка), т.е. случайно; после — `unit_evidence_absent`. Это задача извлечения (промпт C), не слоя решения. Гейт единицы специально ищет единицу и в заголовке столбца над числом, чтобы не блокировать правильно прочитанные ведомости (тип SPZU-027).
4. **Метка отсутствия раздела.** «Раздел отсутствует» утверждается только если на стадии нет ни одного нераспознанного файла. На Тюменской/Новослободской в РД есть нераспознанные файлы, поэтому `MISSING_DOCUMENT` там не появляется (выход не изменился). На ALT79B/IZM12/Речникове в РД распознано всё — там появляются `MISSING_DOCUMENT(RD_MISSING)` для параметров, чей раздел РД не передан (например, ОВ, СС, ППР). Точная граница `MISSING_DOCUMENT` / `COMPARISON_IMPOSSIBLE` у организатора не описана (раздел 1) — это наше прочтение.
5. **Таблица триггеров — один проход** (стоп-условие промпта): 38 из 132 строк помечены `needs_review`. Посевы стенда A содержат только коды с триггером «любое изменение / > x %», поэтому поведение DECREASE/INCREASE/ABS_THRESHOLD/ENUM_DOWNGRADE подтверждено юнит-тестами на каждый тип, а на посевах — только отсутствие FP.
6. **SILVER.** Разметка одним аннотатором той же модели, вторая проверка не проведена; recall по истинным нарушениям на новых объектах не измерим (n = 1).
7. **Не проверялось:** Docker-образ (всё — in-process venv), LLM-верификатор (выключен), ID-стадия почти не участвует (у 3 из 132 параметров каталог называет раздел для ИД).
8. **Вопросы организаторам** (дополняют список в бэклоге): (а) как метить параметр, для которого на стадии нет документа нужного раздела при наличии других документов стадии — `MISSING_DOCUMENT` или `COMPARISON_IMPOSSIBLE`? (б) при двух поколениях ПД в пакете — сравнивать с последним поколением или ставить `COMPARISON_IMPOSSIBLE`?
