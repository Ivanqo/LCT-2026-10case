# S3 — офлайн-загрузка, реестр и качество источников

Дата: 28.09.2026. Реестр файлов разбирается `app/batch_package.py` (S6); отдельный парсер не добавлялся.

## Результат по пунктам

1. **Офлайн-загрузка через UI.** В `routes_upload.py` PDF и реестр проходят через офлайн-пакет под `CASE10_BATCH_PACKAGES_ROOT/_uploads/<project>/<process>/`. Загрузка сохраняется в `files/`, реестр — в `registry/`; далее вызываются `batch_package.build_plan()` и `import_plan()`. Реестр можно загрузить до PDF: первая загрузка документа перечитывает пакет и применяет его строки. При `OFFLINE_DELIVERY=1` RAG не создаётся и не вызывается. Офлайн-файлы и реестры обрабатываются автоматически в профиле демо даже при `API_AUTO_PROCESS_UPLOADS=false`; XML и IFC сохраняют прежнее поведение очереди.

   **Живой проход через UI `evaluation/phase12/s5_demo_serve.py`:** проект «S3 offline queue fallback 2026-09-28», project id `4`; через форму загружены ПД/РД/ИД и Перечень CSV. `build_plan()`/`import_plan()` применили реестр к трём PDF: в панели S5 отображаются стадии П/Р/ИД, редакция `1`, статус «Утверждён», действующая утверждённая версия. При отсутствии broker публикация задания вернула `false`, после чего стандартный `execute_process_job()` запущен в worker thread без RAG. Журнал: процесс `537298a1a531411a9daf97ac7ec98255`, объект `S3-UI-20260927`, job `7a79fdb685644a8cb84e8021c960cfbe`, переход `QUEUED → PROCESSING → READY`, outcome `ready`; создан протокол id `13`, версия `4`. В интерфейсе он выбран и открыт: «Готово к проверке», ПД/РД/ИД загружены, видны действия «Скачать протокол (PDF)» и «Экспорт submission (JSON)». Реестр в списке файлов может отображаться как «Задерживается»: UI S5 опрашивает только DocumentVersion, а реестр хранится как метаданные пакета.

   Интеграционный тест подменяет `RagClient` аварийным исключением и подтверждает, что загрузка PDF/реестра завершается без обращения к RAG. Также он фиксирует вызов inline-выполнения при пустом `RABBITMQ_URL`; с настроенной очередью сохраняется штатная публикация и выполнение consumer.

2. **Хуки S5.** Добавлен `file_registry.py` с `revision_scopes`, `apply_inspector_revision_choice` и `completeness_report`. Формы ответов совместимы с `_s3_hook`; обоснованный выбор инспектора записывается в `InspectorEdit` и ставит новую версию проверки в очередь (`RECOMPUTE_QUEUED`).

3. **Выбор версии и блокировка.** Используются цепочки `predecessor_id/successor_id`, `approval_status` и `approval_date` из импортированной строки Перечня. Единственная утверждённая редакция или единственный утверждённый конец целостной цепочки выбираются автоматически. Несколько утверждённых редакций разрешаются по дате только когда даты есть у всех и единственная дата максимальна; циклы, разветвления, отсутствующие связи, неподтверждённый статус и спорные даты дают `CLARIFICATION_REQUIRED` с основанием. Такой источник не участвует в извлечении значений и создаёт техническую группу без expected/actual. `SUPERSEDED` и `CANCELLED` исключены из эталонов и доказательств; ручной выбор не снимает этот запрет. Обычные корпусные документы без пакетного реестра не блокируются политикой пакета, что сохраняет существующую приёмку 9.3.

4. **Комплектность.** Отчёт объединяет активные источники `source_pd/source_rd/source_id` матрицы, дисциплины и строки без файла из Перечня. В каждой строке возвращаются этап, раздел, ожидаемость и её основание, число найденных/загруженных файлов, файлы, статус и причина неопределённости. В S5 hook также возвращается сводка по стадиям.

5. **LOW_QUALITY.** Кандидатные страницы помечаются при повороте, при отсутствии текстового слоя вместе с недоступным или низкоуверенным OCR (средняя уверенность ниже 55), а также при печати/штампе поверх слов (аннотация PDF или наложенное изображение). На исходном SourceFragment записываются `quality_status=LOW_QUALITY`, `quality_flags` и причины. Фрагменты/наблюдения такой страницы исключаются из извлечения; если нечитаемая страница нужна для сравнения, создаётся `NOT_COMPARABLE` с причиной `LOW_QUALITY`, без значений. Страницы, причины, OCR confidence и поворот доступны в findings протокола и отдельном массиве `quality_issues` JSON-экспорта; UI S5 читает установленный флаг.

6. **ABS_THRESHOLD.** Не реализован: приоритет отдан блокирующим пунктам 1–3 и пунктам 4–5.
