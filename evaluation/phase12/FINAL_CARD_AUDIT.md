- **Дозагрузка через API на временной копии стенда с `CASE10_OFFLINE_DELIVERY=1`:** файл `POST /api/upload` с `process_id` проверяемой проверки → файл зарегистрирован в этой же проверке, пересчёт запущен (в очередь поставлены ~130 параметров), через несколько минут (не более 8 по часам) процесс снова READY; очередь Тюмени 137 → 228 карточек (107 новых, 16 заменено пересчётом, 1 изменилась), решений на момент загрузки не было. **Без `process_id`** (старое поведение) тот же файл создавал **новую** проверку (`get_or_create_open_process` ищет процесс по объекту проекта по умолчанию, а у демо-проверки объект импортированный) — поэтому параметр и добавлен. Без офлайн-режима загрузка падает на `ConnectError` к RAG-сервису (его нет на локальном стенде).

## 5. Что не сделано / риски / от чего зависит

1. **Дозагрузка через окно в браузере целиком не прогнана**: окно открывается, но выбрать файл в headless-Chromium скриптом не вышло; прогнаны сам эндпоинт и логика «до/после» на сводке очереди. 3. **После дозагрузки в демо-пересчёте значение РД карточки M-078/140 сменилось на список из 18 систем (V0.8, V1.0 … V77.73)** — это результат пересчёта на текущем незакоммиченном коде сессии A (`room_drawing_compare.py`), я его не разбирал; сигнал для A/B.
4. **Идентичность источника в карточке — по данным записи** (объект, помещение, этаж/корпус, если есть в `delta`); автоматической проверки, что в ПД и РД речь об одном помещении/этаже, нет — это предмет шага A.
5. **Обозначение листа** найдено в основной надписи ПД; у РД демо (`АНО-150321-1-РД-ОВ1`, стр. 18) в текстовом слое основной надписи нет — показывается «—».
