## 3. Решение

Файлы: `evaluation/export_identity.py` (новый, чистые функции), `evaluation/exporter.py` (`_apply_identity`, `_merged_fragments`; правки внесены с сохранением смешанных CRLF/LF).

Объект сравнения строки: пара таблиц (ПД, РД) = (файл, страница, заголовок) + поле/тип расхождения — для S1; (источник, причина) — для служебной строки; сама группа — для остальных.

1. Сначала сильнейшее утверждение (`VIOLATION_PRESENT` > `MISSING_DOCUMENT` > `NO_VIOLATION` > `COMPARISON_IMPOSSIBLE`; предупреждение качества слабее любого по существу; затем уверенность; затем ключ группы — не позиция в списке) **оставляет прежнее место**. Совпадение с разметкой организатора, которая называет место, не меняется.
2. Остальные объекты места получают в `location` уточнение «`<место> (<что отличает>)`» — только то, что реально различается в наборе: этаж (если различается), РД-том и страница, ПД-таблица (если этаж этого не объясняет), поле (площадь/наименование). Служебным — причина: «предупреждение качества», «запрос уточнения», «отсутствует документ», «значение не извлечено». Исходное место сохраняется в `location_base`, уточнение в `location_qualifier`. Примеры: `этаж 1 (РД ALT79B-000077 стр. 4)`, `6 (этаж 2; РД ALT79B-000077 стр. 5; наименование)`, `OBJ-NEW-ALT79B (предупреждение качества)`.
3. Строки **одного** объекта сравнения: полные дубли (одинаковые статус и значения) — одна запись, чужие ссылки добавлены в `evidence`, идентификаторы групп — в `related_group_ids`; противоречие — побеждает сильнейшее, слабое перечислено в `superseded` (группа, статус, значения, причина), его цитаты в доказательства победителя **не** подмешиваются; слабая запись остаётся в протоколе (его содержимое не менялось).
4. Квалифицированное место не может совпасть с уже занятым (иначе `вариант N`); `finding_id`/`evidence_group_id` считаются от итогового места, поэтому уникальны сами, `_disambiguate_identifiers` остаётся страховкой. У пакета без общих пар экспорт не меняется ни на байт.

Не менялось: `explication_compare.py`, `official_evidence.py`, групповые ключи (`group_key`, решения инспектора), идентификация помещений (шаг A), карточка, очередь, протокол/PDF.

## 6. Ограничения и что осталось

* **Уточнение места видно только в экспорте** (`/submission`, `grader_sim`, файл результата). Очередь, карточка, протокол/PDF и экспорты Z (DOCX/XML) показывают прежнее простое место. Если нужно единое отображение — подключить `plan_identity` (или поле `location_qualifier`) в `protocol_annex2`/карточке; это файлы Z/C1, я их не трогал.
* **Какой из двух томов РД получает простое место при равной силе** (оба `VIOLATION_PRESENT`) — решает хеш ключа группы: детерминированно и не зависит от порядка, но без смысла. Если организатор в скрытой разметке выбрал конкретный том (например АР1), простое место может достаться другому; внутреннего признака «главного» тома нет. Предложение: при равенстве предпочитать более поздний/утверждённый том по реестру (нужно решение, как определять).
* Слияние одного объекта на реальных протоколах не наблюдалось (нет таких случаев в 8 объектах); логика проверена тестами.
* `protocol_to_evaluation_predictions` (путь старого `evaluation/metrics.py`) не менялся: в нём сильнейшая находка и так выбирается при дублях ключа.
* `run_baseline.py`: добавлен необязательный дамп протокола (`CASE10_BASELINE_DUMP_PROTOCOL=1`); по умолчанию поведение прежнее.
* Документация (README_GRADER/DEPLOYMENT) не обновлена (владеют E1/Z). Для неё: новые необязательные поля проверки — `location_base`, `location_qualifier`, `related_group_ids`, `superseded`.
* Данные прогонов: `E:\case10_f1\` (≈ 1,9 ГБ: протоколы, экспорты, база демо) — можно удалить после проверки. Мои процессы завершены.
