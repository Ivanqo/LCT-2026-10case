## 3. Демо одной командой

```bash
python deploy/demo/stand.py up --open     # поднять стенд с готовыми проверками (ALT79B и NOV)
python deploy/demo/stand.py status
python deploy/demo/stand.py down          # остановить, данные остаются
python deploy/demo/stand.py reset --open  # стереть данные и поднять заново
```

Что делает `up`: ссылки на пакеты и реестры в `data/demo_stand/packages` (вне git; источники берутся из `CASE10_NEW_OBJECTS_ROOT` и `CASE10_BENCH_WORK`, как в `demo.py`), `docker compose -p case10demo build`, `up -d` по неизменённому `docker-compose.case10.yml`, ожидание `/health`, вход админом, создание двух проектов и `batch-runs`, ожидание `READY`. Повторный `up` идемпотентен (проверки уже есть, 37 с). Отдельный compose-проект `case10demo` не трогает другие стенды. Перед сборкой, если образов `:hostfix` нет, скрипт ждёт сеть из контейнера (обход «Connection refused» после старта Docker).

Замеры на этом ноутбуке (кэш слоёв Docker тёплый): первый `up` 4 мин 38 с, `reset` 3 мин 54 с (NOV 61 с, ALT79B 148 с), повторный `up` 37 с. Холодная сборка образов ≈ 30 мин (замер из чистого клона, отчёт `E:\case10_clean_gh\REPORT.md`, в репозиторий не входит).

## 4. Глюк «Проверки ещё не запускались»

Объяснение: вкладка «Проверка» показывала пустое состояние, пока не приходил список проверок проекта (до ответа список считался пустым), а подпись вкладки «Проверка (не запущена)» зависела от запомненного в браузере номера проверки. Второй, более серьёзный случай нашёл повторный `reset`: после сброса стенда браузер помнит номер проверки, которой больше нет, и запрашивал её статус бесконечно (404) при пустом экране. Исправлено:

- `ProcessPanel.jsx`: пока список проверок не загружен, показывается «Загружаю список проверок…», а не «ещё не запускались»; ответ 404 на статус запомненной проверки сбрасывает её, и открывается последняя;
- `App.jsx`: при выборе проекта без запомненной проверки подтягивается последняя, подпись вкладки не врёт.

Проверено: запомненный (несуществующий) номер проверки подменён на актуальный, экран открывается. `npm run lint` и `npm run build` чистые.
