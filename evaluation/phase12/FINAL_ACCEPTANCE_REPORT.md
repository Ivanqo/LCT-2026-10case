## 8a. Критический риск входа данных (реестр и импорт)

**Суть.** Результат CLI зависит от реестра сильнее, чем от OCR. На TYU живой набор 0/10 в Docker-CLI против 4/10 «по ключу» на хосте; находки M-078/M-079 (12 кандидатов на хосте) теряются при всех трёх вариантах реестра, которые я пробовал.

| вариант реестра TYU (57 файлов) | итог | причина (проверено прогоном) |
|---|---|---|
| из манифеста: стадия РД/ПД, без `approval_status` | 0 находок, 129 `CLARIFICATION_REQUIRED` | все документы: `revision_clarification_required: approval_status=UNKNOWN` (правило редакций) |
| + `approval_status=APPROVED` | 0 находок, 129 `MISSING_DOCUMENT` | стадия РД задана реестром (приоритет над путём), в пакете нет ИД → `missing_stage` для параметров с ИД |
| + `APPROVED`, стадия не указана (берётся по папкам) | 0 находок, 129 `mixed_stage_requires_review`, 22 `LOW_QUALITY` | папка «Рабочая и исполнительная документация» = `RD_ID_MIXED`, как и на хосте (там 128) |

После третьего варианта различие с хостом по причине отказа исчезло, но **кандидатов M-078 по-прежнему нет (на хосте 12)**: что именно в хостовом импорте (`import_official_dataset` / `run_baseline.py`) даёт правилу S2 вход, которого нет у импорта CLI (`batch_package`), я не установил — это нерешённый вопрос, не вывод. Гипотеза без проверки: метаданные документов (раздел/стадия/датасетные поля), которые хостовый импорт проставляет и которые читает `official_rule_packs`.

**Как реестр организатора с «типичными синонимами» поведёт себя — по коду `batch_package.py`, прогоном НЕ проверено:**
- Заголовки: распознаются синонимы (`stage/стадия`, `section/раздел/марка`, `status/статус`, `code/шифр`, `rev/редакция/изм`, `path/filename/имя_файла/файл` …); **нераспознанный заголовок молча отбрасывается** (например «Статус документа», «Стадия разработки») → поле пусто → `approval_status=UNKNOWN` у всех файлов → массовое `CLARIFICATION_REQUIRED`, без сообщения о причине на уровне пакета.
- Стадия: ищется слово из `PD/П/ПД/PROJECT/ПРОЕКТНАЯ`, `RD/Р/РД/WORKING/РАБОЧАЯ`, `ID/ИД/AS_BUILT/ИСПОЛНИТЕЛЬНАЯ`; другое значение («Стадия П» распознаётся, «Раздел ПД» — да, «Проект» — нет) → стадия берётся по папкам, при смешанной папке — `RD_ID_MIXED`.
- Статус: приводится к верхнему регистру с `_`; допустимы только `DRAFT, APPROVED, FOR_CONSTRUCTION, SUPERSEDED, CANCELLED`. **Русские значения («Утверждено», «В производство работ») → `UNKNOWN_APPROVAL_STATUS` → пакет `CLARIFICATION_REQUIRED`**, сравнение блокируется.
- Раздел: значение проходит как есть, без таблицы синонимов; совпадение кода `OV` с `ОВ` (латиница/кириллица) и прочих обозначений разделов с каталогом **не проверялось**.
- Файл сопоставляется по SHA-256, затем по имени; расхождение SHA-256 → `SHA256_MISMATCH`; файл вне реестра → `NOT_IN_REGISTRY`.
