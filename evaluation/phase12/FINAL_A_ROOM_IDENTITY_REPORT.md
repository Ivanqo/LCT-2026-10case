## 1. Что исправлено — по трём замечаниям экспертов

**№1. Перезапись помещений с одинаковым номером.**
Воспроизведено на старом коде: ПД `101/P1` + `101/V2`, РД `101/V2` → порядок `[P1,V2]` даёт `[]`, порядок `[V2,P1]` даёт
`missing=[P1]`. Теперь:
- ключ помещения = (корпус, этаж, номер); корпус и этаж читаются из текста листа (`detect_sheet_context`: «План N этажа»,
  «Экспликация помещений N этажа / подвала», «План на отм. …», «Корпус/секция N»). Просто «2 этаж» в легенде или в
  названии помещения этаж листа не задаёт; «Схема … 1 этаж» тоже (схема называет обслуживаемый этаж, не этаж помещений).
  Несколько разных этажей на листе или ни одного → этаж не определён (`floor_status` = multiple / not_found), не угадывается;
- если этаж не определён, область ключа — лист (документ + страница): помещения разных листов не склеиваются по номеру;
- два разных набора систем под одним полным ключом в одной стадии → `CONFLICT`, причина `DUPLICATE_ROOM_KEY`, все записи
  сохранены, решение не выносится; идентичные дубликаты сливаются;
- ПД↔РД: этаж известен с обеих сторон — сопоставление по этажу; неизвестен с одной стороны и кандидатов несколько →
  `AMBIGUOUS` / `AMBIGUOUS_ROOM_MATCH`; единственный кандидат при неизвестном этаже — сопоставление «только по номеру»
  (`match_basis="room_number_only"`, явно помечено). Результат не зависит от порядка (перестановочный тест);
- одинаковый номер дважды на одном листе — два экземпляра (раньше второй затирал первый); зона `duplicate_on_sheet`;
- в правилах ОВ (`official_rule_packs`) `expected_rows`/`working_by_location`/выбор страницы РД по номеру заменены на
  ключ идентичности; если один номер принадлежит нескольким помещениям, `location` наблюдения получает уточнение
  («101 (этаж 2)», «012 (док. 25, лист 104)»), иначе остаётся напечатанный номер (для экспорта и сверки он прежний);
- два листа ПД без определённого этажа претендуют на одно помещение РД: решает этаж (если известен с обеих сторон), затем
  число общих номеров помещений на листах (≥ 3 и ≥ 2× больше, чем у соперника), иначе никто не выбирается
  (`AMBIGUOUS_ROOM_MATCH`);
- проблемы идентификации превращаются в группы `CLARIFICATION_REQUIRED` с источниками (файл, страница, bbox) —
  `official_evidence._upsert_room_identity_groups`.

**№2. Привязка системы к помещению.**
- для каждой подписи считаются все помещения в окнах (окна прежние); если лучший кандидат не опережает второго на
  `AMBIGUITY_MARGIN` = 10 % (относительная разность расстояний), подпись — «неоднозначна»: возвращается список кандидатов,
  привязка не назначается (`room_system_links()["ambiguous"]`);
- уверенность разделена: `text_confidence` — реальный OCR-балл (теперь из `x_wconf` Tesseract, раньше стояло выдуманное
  0,68), для слов текстового слоя PDF — `None`; `link_confidence` — геометрическая оценка ранжирования (близость внутри
  окна + запас над вторым кандидатом, штраф за привязку «в той же строке»), **не вероятность**; `confidence` оставлено для
  совместимости как минимум из измеренных, где ничего не измерено — `UNMEASURED_CONFIDENCE = 0,5`. Фиксированных
  0,88 / 0,72 / 0,8 / 0,75 больше нет; `RuleObservation` получил поля `text_confidence`, `link_confidence`;
- ожидаемая метка, чья привязка в РД неоднозначна, не считается «пропавшей»: вердикт не выносится (проблема
  `AMBIGUOUS_SYSTEM_LINK`) — только если неоднозначная метка могла бы изменить ответ правила; если не могла,
  вердикт остаётся и это записано (`ambiguity_not_decisive`);
- стены: `wall_check="not_evaluated"` в каждой строке и в отчёте. Линии стен через `fitz.get_drawings` не добавлялись:
  снимок страницы (`dataset_sources._original_page_snapshots`) несёт только слова; вносить векторный разбор в общий
  загрузчик страниц за отведённое время и без риска для остальных правил не стал.
  Остаточный риск: подпись за стеной от помещения так и не отличается от подписи внутри.

## 3. Места, которые ещё держат ключ только по номеру

- `explication_compare._keyed`: ключ строки таблицы — номер внутри одной таблицы; повторы **пропускаются** с записью в
  `notes` («ambiguous keys skipped»), а не перезаписываются, но в протокол как запрос уточнения не выходят. Пары таблиц
  сопоставляются по области таблицы, не по помещению. Не менял.
- `official_evidence._upsert_rule_groups`: `group_key = f"loc:{location}"`. Для ОВ локация теперь уникальна
  (суффикс при повторе номера), для остальных кодов правил (PZ/KR) локации — не номера помещений.
- Резервный разбор текста вокруг помещения (`_text_in_bbox` + `_extract_exhaust_systems`, прежний путь, когда привязка по
  метке не нашла систему) читает метки из окна вокруг номера и не знает о соседних помещениях: ожидаемая метка рядом с
  чужим номером всё ещё может попасть в значение РД этим путём. Не менял (это его прежнее поведение).
- `_pd_supply_room_links` (венткамеры, M-079): добавлена проверка «подпись венткамеры ближе к одному номеру, чем к
  следующему» (тот же запас), но привязка установки к венткамере по расстоянию ≤ 0,08 остаётся эвристикой.

## 5. Остаточные риски и решения для шага B

1. **Потеря 140 и 012 в живом прогоне** (были верными по разметке). Причина — отсутствие этажа/корпуса на ПД-листах
   (лист на три этажа, схемы установок) и несколько ПД-листов с одним номером помещения. Возможные пути (не делал, нужно
   решение): извлекать этаж не только из заголовка, но из соседних подписей/экспликаций; либо в шаге B вывести такие
   случаи в протокол как «предположение для верификации» с кандидатами, а не как запрос уточнения.
2. Добавленные системы (`added_systems`) пока только в контексте извлечения, не в протоколе — это вход для шага B.
3. Эвристика этажа читает полный текст страницы: заголовок «План … N этажа» в тексте легенды или перечне листов может дать
   ложный этаж; несовпадение известных этажей считается несовпадением помещений (так и задумано), поэтому ложный этаж
   даёт пропуск, а не ложное нарушение.
4. Стены не проверяются (`wall_check="not_evaluated"`): подпись по другую сторону стены от помещения неотличима.
5. `link_confidence` — ранжирующая оценка, а не вероятность; в карточке и протоколе так и должна называться.
6. Локальный Tesseract этой машины падает (код 0xC0000005 при OCR страниц, как и в P0): фоновая OCR-часть прогонов
   TYU/NOV деградирована и в «до», и в «после» одинаково.
