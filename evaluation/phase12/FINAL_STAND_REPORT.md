## 1. Что исправлено

### D1 — «database is locked» при входе/записи во время обработки
Причина (подтверждена): `run_process` открывал запись первым `flush` и держал единственную блокировку записи SQLite до финального `commit` — всю разметку страниц/OCR (минуты); журнал по умолчанию (`delete`) и `timeout` 5 с.

* `api_service/app/db/session.py`: для **sqlite-соединений** (событие `connect`) `PRAGMA busy_timeout` ≥ 30 000 мс (по умолчанию 60 000, `API_SQLITE_BUSY_TIMEOUT_MS`), `journal_mode=WAL`, `synchronous=NORMAL`; `connect_args timeout` и сырое соединение миграций — тоже 60 с. Если файловая система не даёт WAL, режим остаётся прежним (ошибка pragma проглатывается), отключение: `API_SQLITE_WAL=0`. Postgres не затронут.
* `release_write_lock(db)` (там же): для sqlite коммит без сброса загруженных объектов (`expire_on_commit` выключен на время коммита), для других диалектов ничего не делает. Вызывается на границах стадий, где нет открытой записи, а дальше идёт долгая работа без БД: после подготовки процесса (`v3_pipeline.run_process`), после живого тэггера, после проверки качества страниц и извлечения правил (`official_evidence.create_official_evidence_groups`). Запись групп/протокола осталась одной транзакцией. Повтор после сбоя безопасен (upsert по ключу группы, лишние группы убирает sweep); частично закоммичены только статус «PARSING», комплектность и кэш-фрагменты тэггера.

### D3 — стадия при загрузке через интерфейс
Причина: оффлайн-путь загрузки кладёт файл в `files/<id_задачи>/<имя>`, а стадия по пути читает только имена **папок** (`stage_from_package_path`) → всегда «Не указано», комплектность `PARTIALLY_LOADED`.

Ровно одна стадия → назначается (источник FILENAME/FOLDER); несколько («ПД_РД», «Рабочая и исполнительная») → стадия **не назначается**, предупреждение; нет слов («Рядовой проект», «Идея», `doc_id123`) → ничего, без угадывания.
* `batch_package.build_plan(..., stage_fallback=None)`: необязательный параметр, вызывается последним (реестр и папка стадии не перебиваются). CLI/batch-runs его не передают — путь **не изменён** (тест + побайтно прежний `result.json`). Только `routes_upload._import_offline_upload_package` передаёт `stage_from_name`.
* `official_dataset._live_index_row` сохраняет стадию с источником FILENAME/FOLDER (раньше — только REGISTRY), иначе импорт заменял её на UNKNOWN.
* `GET /case10/documents`: поля `stage_source`, `stage_source_label` («по имени файла», «по реестру», «по папке пакета»), `stage_warning`.
* UI (`DocumentsPanel.jsx`): под файлом «Стадия по имени файла • …», красное предупреждение для неоднозначных; заголовки групп «ПД/РД/ИД» (раньше бэкенд-метки «П/Р/И»); подсказка обновлена. `npm run lint` и `npm run build` — чисто.

### p95 `protocols/current`
`api_service/app/domain/protocol_body_cache.py` + 10 строк в маршруте. Ключ: (организация, проект, process_id) + идентичность последнего протокола из БД без payload (id, версия, статус, created_at, finalized_*, unfinalized_*, длина payload в байтах). Хит отдаёт готовые байты; промах строит тело прежним `_compact_json_response`. Объём: 8 записей (LRU). Любая вставка/изменение/удаление `Protocol` в процессе (решение инспектора → новая версия, финализация, снятие, синхронизация ИАИС РиН) очищает кэш; изменение из другого процесса (воркер) меняет идентичность → другой ключ.
Тесты `test_case10_stand_protocol_cache.py` (4): тело побайтно = безкэшевому ответу, второй запрос — хит; решение инспектора отражается сразу (версия+1, статус CONFIRMED_VIOLATION, старый ответ не отдаётся); in-place правка payload сбрасывает кэш; ограничение размера и область ключа.

Замер: реальный протокол ALT79B (стенд `demo.py live alt79b`, ответ 2 593 952 Б), 100 запросов подряд по keep-alive, один и тот же файл БД, код «до» и «после» по очереди:

**Gzip (не включён, `CASE10_API_GZIP=0`).** Измерено с `CASE10_API_GZIP=1` и `Accept-Encoding: gzip`: напрямую 2,59 МБ → 149 009 Б (÷17), p50/p95 37,6/52 мс (на localhost медленнее несжатого из-за CPU); **через шлюз :8080 ответ ломается**: приходит `Content-Encoding: gzip` и `Content-Length: 2593952`, а тело уже распаковано `fetch` (проверка `gzip.decompress` → «Not a gzipped file») — браузер не прочитает.
