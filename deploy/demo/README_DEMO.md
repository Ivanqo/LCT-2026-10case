# Демо CASE10 — сквозной прогон: загрузка комплекта → протокол

Что показываем: комплект документов (папка + реестр файлов) → процесс проверки → кандидаты, предположения и гипотезы →
карточка с синхронными ПД/РД/ИД и подсветкой → решение инспектора → протокол (PDF/JSON). Оценивается функциональность
карточки по чек-листу экспертов (`evaluation/phase12/FINAL_CARD_AUDIT.md`), не дизайн.

Всё в этой папке — данные и вспомогательные скрипты стенда; логика проверки в них не зашита (идентификаторы объектов,
пути и ожидаемые находки лежат в `packages.json` и `expected/*.json`).

## 0. Памятка для показа на ноутбуке (Docker, одна команда)

Стенд на готовых образах с уже выполненными проверками: объект **Алтуфьевское, 79Б** (5 нарушений-кандидатов, 34 предположения)
и **Новослободская** (0 кандидатов: система не выдумывает нарушения). Всё в Docker; сеть нужна только при первой сборке образов.

| Что | Команда (из корня репозитория) | Время |
|---|---|---|
| поднять стенд с готовыми проверками | `python deploy/demo/stand.py up --open` | образы уже собраны: ≈ 5 мин (пакеты, запуск, две проверки); первая сборка образов ≈ 30 мин |
| состояние | `python deploy/demo/stand.py status` | секунды |
| остановить (данные и проверки остаются) | `python deploy/demo/stand.py down` | секунды |
| сбросить всё (решения, загрузки) и поднять заново | `python deploy/demo/stand.py reset --open` | ≈ 5 мин |

Адреса: интерфейс http://127.0.0.1:3100, API http://127.0.0.1:8000/docs, шлюз http://127.0.0.1:8080/openapi.json. Вход
`admin` / `Case10-Demo-2026`. Другие порты: `UI_HOST_PORT`, `API_HOST_PORT`, `GATEWAY_HOST_PORT` (скрипт сам собирает интерфейс
под адрес шлюза). Тег образов: `CASE10_IMAGE_TAG` (по умолчанию `hostfix`; существующие образы переиспользуются, недостающие
собираются). Стенд живёт в отдельном compose-проекте `case10demo` и не трогает другие контейнеры и тома.

Пакеты организатора в репозиторий не входят: скрипт берёт их из папок `CASE10_NEW_OBJECTS_ROOT` (`Алтуфьевское, 79Б`) и
`CASE10_BENCH_WORK` (`public_docs/NOV` + манифест), как и `demo.py`; ссылки на файлы и реестры (`approval_status=APPROVED`,
реестр составлен нами) создаются в `data/demo_stand/packages` (вне git, `--home` меняет папку).

**Перед показом:** Docker Desktop запущен (зелёный значок), закрыты тяжёлые приложения, `python deploy/demo/stand.py status`
показывает оба проекта в `READY`.

**Если Docker «Connection refused» после старта** (сборка падает на `apt-get update`, `docker run` не достаёт внешние хосты):
подождите 1–2 минуты после запуска Docker Desktop и повторите команду; скрипт сам ждёт сеть перед сборкой. Не помогло —
`wsl --shutdown`, перезапустить Docker Desktop, повторить `up`. Если Docker Desktop не стартует из-за битых сокетов, переименуйте
папку `%LOCALAPPDATA%\Docker\run` и запустите его снова. Обрыв загрузки зависимостей при сборке: повторить `up` (слои кэшируются).

**Экраны для показа (≈ 5 мин):**
1. «Панель объектов»: Алтуфьевское — красный (5 кандидатов, 34 предположения), Новослободская — зелёный.
2. Проект «Демо: Алтуфьевское, 79Б» → «Проверка» → карточка M-002 (антресоль): ПД 71.01 и РД 71.77 рядом, рамки с подписями,
   «Основание расхождения», «Отклонить» без комментария не сохраняется; «ИД: документы не загружены» → «Дозагрузить».
3. «Сравнение листов» (первый раз считается до минуты): пара листов, процент сходства, области различий.
4. «Документы»: перетащить четыре файла «ПД …», «РД …», «ИД …» — стадия определяется по имени файла, сценарий «ПД + РД + ИД».
5. Экспорт: «Скачать протокол» PDF, DOCX, XML, «Экспорт результата» JSON.
6. «Отчёт ML» и «Нормативная база» — если спросят про дообучение и пороги.

Пошагово (то же самое):

| Шаг | Команда | Время (тёплый кэш, эта машина, 3 процесса тэггера) |
|---|---|---|
| проверка готовности (OCR, модель, пути, порты, флаги) | `python deploy/demo/demo.py check` | ≈ 10 с |

Флаги демо (`packages.json`): `CASE10_EXPLICATION_COMPARE=1` (S1), `CASE10_ROOM_DRAWING_COMPARE_ENABLED=1` (S2),

## 2. Docker (образ с рабочим OCR)

Демо рассчитано на Docker-образ, где Tesseract 5.5 с русским языком уже установлен; на машине без него (или со старым
Tesseract 3.x) листы-сканы читаются хуже. Образ **не пересобирался** в этой работе.

```bash
python deploy/demo/demo.py --docker start                 # api + worker + rabbitmq + шлюз из docker-compose.case10.yml + флаги демо
python deploy/demo/demo.py --docker --mount-code start    # то же, но код из рабочего дерева монтируется поверх СТАРОГО образа (только для проверки до E1)
python deploy/demo/demo.py live tyu                       # дальше команды те же: они говорят с API на :8000
python deploy/demo/demo.py --docker stop
```

Контейнер интерфейса не поднимается: тот же собранный `frontend_react/dist` отдаёт локальный `ui_server.py` (он же даёт адрес
`/go`). Пакеты монтируются из `<home>/packages` в `/data/packages` (`CASE10_PACKAGES_DIR`). Резервная заготовка в Docker —
`demo.py --docker all <pkg>` (запускает прогон с пометкой «Заготовка» через тот же API; БД живёт в томе `case10_data`).
**Что должен проверить E1 в образе:** `check` (внутри образа `tesseract --version` = 5.5 и `rus` в списке языков), `live tyu`
и `live alt79b` — число находок и SHA-256 `result.json` совпадают с таблицей §3; время холодного/тёплого прогона.

### Допущения демо-реестра (говорить прямо, если спросят)

Перечень ИД 1.1 требует статус утверждения у каждого файла; у организаторских комплектов его нет, а без него система
(правильно) воздерживается. Поэтому реестр демо составлен нами (`demo.py stage`): каждому файлу проставлено
`approval_status=APPROVED` и одна дата; папка Тюмени «рабочая и исполнительная документация» разнесена по именам (АОСР и
«Исполнительный чертеж…» → ИД, остальное РД); коды разделов (OV→ОВ …) приведены к принятым в реестре. Это не данные
организатора: в реальном комплекте столбцы заполняет заказчик.

## 4. Сценарий показа (≈ 8–9 мин, из них живой прогон ≈ 2 мин на фоне рассказа)

1. (0:00) `live tyu` запущен заранее перед слайдом «Сквозной сценарий»; пока идёт — рассказ про уровни выдачи и честные состояния.
2. (2:00) Открылась проверка Тюмени: прогресс (документы/листы, «Охват неполный» — ИД не загружена), очередь: нарушения-кандидаты → предположения.
3. Карточка M-078 / помещение 142: панели ПД и РД рядом, рамки с метками «значение · стадия», строка идентичности (объект, элемент), источник стадии (реестр ПД · классификация), лист и страница; **масштаб** до читаемой подписи, «Фрагмент» — возврат; панели независимы ↔ синхронны; полный экран.
4. «Основание расхождения»: правило, величина «не вычислялось» (для набора систем разность не считаем), уверенности раздельно, **вероятность не заявляется**.
5. Решение: «Отклонить» без причины не сохраняется; «Подтвердить» с обоснованием; «Разделить на части» для составного.
6. Неполный комплект: «ИД: документы не загружены» → «Дозагрузить» (показать окно, не обязательно грузить).
7. Протокол: «Перейти к записи протокола», PDF; финализация → предупреждение «ИД не загружена».
8. Если время есть: проект `alt79b-hyp` — карточка гипотезы (метод, уверенность, ссылки, статус) → «Преобразовать в кандидата».

## 5. Если что-то сломалось (запасной сценарий)

| Симптом | Действие |
|---|---|
| живой прогон дольше 4 минут / падение | не ждать: `demo.py open tyu --prefer prepared` — откроется заготовка «[Заготовка] Тюмень …» (та же БД, те же находки), рассказ идёт по ней; причину искать после |
| стенд не стартует (порт занят) | `demo.py stop`, затем `start`; порты 3100/8000/8080 |
| в базе остались решения прошлой репетиции | `demo.py reset` (возвращает к состоянию после `prepare`) |
| нет заготовки (пустая база) | `demo.py prepare tyu alt79b nov alt79b-hyp` (≈ 4–5 мин), затем `start` |
| листы не открываются (404 страницы) | проверить `CASE10_ORIGINALS_ROOT` = `<home>/packages` (`check`), перезапуск стенда |
| не отвечает браузер/панель | открыть `http://127.0.0.1:3100/go?project=<id>&process=<id>` вручную (адрес печатает `live`/`open`) |
| `verify` показывает расхождение | код/флаги/кэш изменились после репетиции: сравнить `check`, пересоздать заготовку, не показывать «живой» до совпадения |
| совсем ничего | слайды со скриншотами `evaluation/phase12/demo_screens/` + `FINAL_DEMO_REPORT.md` |
